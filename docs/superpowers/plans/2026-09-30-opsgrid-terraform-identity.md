# OpsGrid Terraform Identity Infrastructure 实施计划

> **面向 Agent 执行者：** 必需子技能：使用 `superpower-subagent-driven-development`（推荐）或 `superpower-executing-plans` 按任务逐项执行本计划。步骤使用复选框（`- [ ]`）语法进行跟踪。

**目标：** 为 OpsGrid Phase 1 创建可复用的 Cognito Terraform module、`dev/persistent/identity` 本地 state root、文档和安全忽略规则。

**架构：** `infra/terraform/modules/cognito` 只声明 Cognito resources；`infra/terraform/environments/dev/persistent/identity` 作为唯一可执行 root，通过显式 local backend 拥有独立 state。当前 root 创建 confidential Cognito App Client，让 React custom login 通过 NestJS BFF 使用 `USER_PASSWORD_AUTH`，并预留同一 client 的 OAuth Authorization Code/Google 路径。

**技术栈：** Terraform `>= 1.6.0, < 2.0.0`、HashiCorp AWS provider `~> 6.0`、Amazon Cognito User Pools、React/Vite frontend、NestJS BFF。

**规格：** `docs/superpowers/specs/2026-09-30-opsgrid-terraform-identity-design.md`

## 全局约束

- Project name is `opsgrid`; environment name is `dev`.
- The only implemented lifecycle is `dev/persistent/identity`; no `bootstrap/` directory is created.
- The identity root uses an explicit local backend at `terraform.tfstate`; the state is not committed.
- `modules/cognito` is reusable; project and environment are passed as variables and are not hardcoded inside the module.
- The current App Client is confidential: `generate_secret = true`.
- The current App Client enables `ALLOW_USER_PASSWORD_AUTH` and `ALLOW_REFRESH_TOKEN_AUTH`; the NestJS BFF supplies `SECRET_HASH` and keeps Cognito tokens server-side.
- Optional OAuth uses only Authorization Code flow and scopes `openid`, `email`, and `profile`; implicit flow is not configured.
- Google IdP is disabled by default and requires supplied credentials plus a managed-login domain.
- Google client secrets and Cognito client secrets are never outputs, frontend configuration, example tfvars values, or committed files.
- Terraform state can contain generated client secrets and must be protected even though it is Git-ignored.
- No Secrets Manager, VPC, ECS, EKS, EC2, RDS, Redis, ALB, monitoring stack, application storage, or Cognito Groups are created.
- No `prevent_destroy` lifecycle rule is added; development User Pool deletion protection must remain inactive.
- Resources are tagged with `Project`, `Environment`, `ManagedBy`, and `Component` wherever the AWS provider resource supports tags.
- Do not claim `terraform apply` success without AWS credentials and an actual apply result.

### Task 3: 实现 Cognito User Pool and development security settings

**文件：**
- 修改：`infra/terraform/modules/cognito/main.tf`

- [ ] **步骤 1：add the User Pool resource.**

Add `aws_cognito_user_pool.this` with:

```hcl
resource "aws_cognito_user_pool" "this" {
  name                = "${var.project_name}-${var.environment}"
  username_attributes = ["email"]
  auto_verified_attributes = ["email"]
  deletion_protection = "INACTIVE"
  mfa_configuration   = "OFF"
  username_configuration {
    case_sensitive = false
  }
  account_recovery_setting {
    recovery_mechanism {
      name     = "verified_email"
      priority = 1
    }
  }
  password_policy {
    minimum_length                   = 12
    require_lowercase                = true
    require_uppercase                = true
    require_numbers                  = true
    require_symbols                  = false
    temporary_password_validity_days = 7
  }
  verification_message_template {
    default_email_option = "CONFIRM_WITH_CODE"
    email_subject        = "Confirm your OpsGrid account"
    email_message        = "Your OpsGrid verification code is {####}."
  }
  schema {
    name                     = "email"
    attribute_data_type      = "String"
    required                 = true
    mutable                  = true
    string_attribute_constraints {
      min_length = "0"
      max_length = "2048"
    }
  }
  schema {
    name                = "name"
    attribute_data_type = "String"
    required            = false
    mutable             = true
    string_attribute_constraints {
      min_length = "0"
      max_length = "2048"
    }
  }
  tags = local.common_tags

  lifecycle {
    precondition {
      condition     = length("${var.project_name}-${var.environment}") <= 128
      error_message = "The combined project_name-environment Cognito User Pool name must not exceed 128 characters."
    }
  }
}
```

Use standard schema blocks for required mutable `email` and optional mutable `name` attributes. Keep the schema definitions compatible with Cognito standard attributes; do not add custom tenant/RBAC attributes. Do not add a `user_pool_add_ons` block; advanced security mode is outside this Phase 1 scope and is not represented as an `OFF` value.

### Task 5: 实现 optional managed-login domain and Google IdP

**文件：**
- 修改：`infra/terraform/modules/cognito/main.tf`

**接口：**
- Domain is created with `count = var.create_user_pool_domain ? 1 : 0`.
- Google IdP is created with `count = var.enable_google_identity_provider ? 1 : 0`.
- Client dependency ordering remains valid when either optional resource is absent.

- [ ] **步骤 1：add the Cognito managed-login domain and default branding.**

Add:

```hcl
resource "aws_cognito_user_pool_domain" "this" {
  count                 = var.create_user_pool_domain ? 1 : 0
  domain                = var.cognito_domain_prefix
  managed_login_version = 2
  user_pool_id          = aws_cognito_user_pool.this.id

  lifecycle {
    precondition {
      condition     = length(trimspace(coalesce(var.cognito_domain_prefix, ""))) > 0
      error_message = "cognito_domain_prefix must be non-empty when create_user_pool_domain is true."
    }
  }
}

resource "aws_cognito_managed_login_branding" "this" {
  count                      = var.create_user_pool_domain ? 1 : 0
  client_id                  = aws_cognito_user_pool_client.this.id
  use_cognito_provided_values = true
  user_pool_id               = aws_cognito_user_pool.this.id

  depends_on = [aws_cognito_user_pool_domain.this]
}
```

The branding resource applies Cognito-provided defaults so enabling the domain produces usable managed-login pages without requiring a manual branding step. Do not create a custom certificate/domain resource; only the Cognito prefix domain and default branding are in scope.

- [ ] **步骤 2：add the optional Google provider.**

Add:

```hcl
resource "aws_cognito_identity_provider" "google" {
  count         = var.enable_google_identity_provider ? 1 : 0
  user_pool_id  = aws_cognito_user_pool.this.id
  provider_name = "Google"
  provider_type = "Google"

  provider_details = {
    authorize_scopes = "openid email profile"
    client_id        = var.google_client_id
    client_secret    = var.google_client_secret
  }

  attribute_mapping = {
    email = "email"
    name  = "name"
  }

  lifecycle {
    precondition {
      condition     = var.create_user_pool_domain
      error_message = "enable_google_identity_provider requires create_user_pool_domain to be true."
    }
    precondition {
      condition     = length(trimspace(coalesce(var.google_client_id, ""))) > 0
      error_message = "google_client_id must be non-empty when Google is enabled."
    }
    precondition {
      condition     = length(trimspace(coalesce(var.google_client_secret, ""))) > 0
      error_message = "google_client_secret must be non-empty when Google is enabled."
    }
  }
}
```

The resource must never appear when the flag is false. Do not put Google credentials in locals, outputs, README examples, or tags.

Keep the App Client `depends_on` relationship to `aws_cognito_identity_provider.google` so that enabling Google creates the provider before the client references `supported_identity_providers`. Confirm `count = 0` does not produce an invalid reference.
